# 原作风格与 UI 规范（写之前先看这一页）

这份文档不是“建议”，是本模组接原作时的验收标准。写新段落、改旧段落都按这里来。

## 一、原作者的思路

1. **玩家不是在“做任务”，是在“过日子”**。事件从地点、天气、钟点、NPC 的日常里长出来，不是从任务菜单里发出来。
2. **线索靠人嘴和物件**。谁提了一句、哪张纸上写了什么、哪扇门后面有声音；不靠系统弹窗、不靠“发现新地点”提示。
3. **失败是生活的一部分**。失败不读档、不扣存款、不写“任务失败”，而是把玩家推到另一条具体处境里：被赶出去、错过换班、欠了人情、衣服湿透。
4. **地点有记忆**。熟客记得你、东家记得你上次出错、门卫记得你给过钱。同一地点第二次去，文本要变。
5. **性内容服务于关系和处境**，不是通关奖励。写暧昧、紧张、疲惫、温柔，不写流程化的性描写。
6. **不做系统感**。没有 Lv、没有经验条、没有任务清单、没有“1/3”、没有勾选、没有“奖励已领取”。

## 二、段落长度与节奏

- 一个 passage 只写**一个瞬间**。跨步骤就拆 passage。
- 正文一般 **60–200 个汉字**；最多 250。超过就拆，不要一段写四百字。
- 开头一两句写“你看到/听到/闻到什么”，中间写“发生了什么”，结尾最多一句留白。
- 环境/天气只写 **1 句**，不要每段都写。
- 一段里 NPC 对话最多 **2–3 句**，用「」；不要长篇演讲。

## 三、行动区格式

正文和选项之间空一行（`<br><br>`），每个选项单独一行：

```
<<getouticon>><<link [[离开钟表铺 (0:02)|High Street]]>><<pass 2>><<set $eventskip to 1>><<endevent>><</link>>
<br>
<<socialiseicon>><<link [[问她怀表的来历 (0:06)|MP NPC Sera Chat]]>><<pass 6>><</link>>
<br>
<<investigateicon>><<link "凑近灯下看齿轮咬合 (0:04)">><<pass 4>><<replace "#sera-choices">>……<</replace>><</link>>
<br>
<div id="sera-choices"></div>
```

规则：

1. **移动/离开选项放最上面**，本地动作放下面。玩家先看到“能去哪”，再看到“能做什么”。
2. 离开用 `<<getouticon>>`，走动用 `<<walkicon>>`，调查用 `<<investigateicon>>`，交谈用 `<<socialiseicon>>`，潜行用 `<<sneakicon>>`，跑动用 `<<runicon>>`，买东西用 `<<shopicon>>`。
3. **不是每个选项都要图标**。闲聊、追问、沉默、等待这类选项不加图标；一段里图标最多 3–4 个。
4. 同一段里选项 **2–4 个**最舒服，最多 5 个。超过就拆成两段。
5. 内联结果用 `<<link "动作 (0:04)">>` + `<<replace "#id">>` + `<div id="id"></div>`，不要跳到新 passage 再跳回来。
6. 选项标签以**动词开头**，不超过 12 个汉字，不加句号。

### 好标签 / 坏标签

| 好 | 坏 | 原因 |
| --- | --- | --- |
| 撬开牡蛎暗槽 | 成功撬开暗槽获得 £3 | 写结果、写奖励 |
| 问她怀表的来历 | 任务：询问塞拉（1/3） | 系统感 |
| 蹲下查看绳结 | 检查线索 | 太抽象 |
| 把湿外套挂到炉边 | 休息并恢复体力 | 写数值 |
| 婉拒同乘 | 拒绝（后果：好感 -1） | 写后果 |

## 四、检定与后果

- 有检定的动作先写检定，再写成功/失败两段具体文本：

```
<<set $skulduggerydifficulty to 300>><<skulduggerycheck "silent">>
<<if $skulduggerysuccess is 1>>
	<span class="green">你顺着节拍顶起内侧弹子，锁扣应声弹开。</span><<stress -2>>
<<else>>
	<span class="red">银簪在锁芯里打滑，划伤了脚踝。</span><<pain 3>><<stress 4>>
<</if>>
```

- 属性检定直接写 `<<if $athletics gte 260>>` / `<<else>>`。
- **失败不扣现有存款**，不加任务进度；只加压力、疲劳、疼痛、暴露、怀疑，或换一条分支。
- 成功也不要每次都给钱。给物件、给钥匙、给一句情报、给熟客的信任，比给钱更像原作。
- 颜色 span 只包结果句：`green` 成功、`red` 失败、`gold` 钱、`teal` 中性。正文叙述不要整段染色。

## 五、时间与移动

- 每个动作都要有 `<<pass N>>`，标签里写 `(0:NN)`。
- 移动 2–6 分钟；短动作 3–8 分钟；一段完整班次 15–25 分钟；睡觉/长途另算。
- 同一地点内的动作不要写 `(0:00)`；写 2 分钟以上。
- 跨区域移动要有“路上”的一句，不要点一下就到。

## 六、日志

- 日志是**短叙事**，不是任务清单。
- 好：「你答应过这几天再去钟表铺看看塞拉。」
- 坏：「塞拉任务：阶段 3/10，未完成。」
- 节日倒计时只在最近 7 天出现；小节令不进日志。

## 七、文风

- 多用具体名词：黄铜、亚麻、煤油、牡蛎壳、松脂、粗麻绳。
- 少用形容词堆砌和网文腔：不写“命运的齿轮开始转动”“仿佛过了一个世纪”“不禁心头一颤”。
- 第二人称，短句为主；一段里不要连续三个“你……”。
- 不写“你成功了”“任务完成”“获得奖励”“系统提示”。
- NPC 说话要有身份：裁缝说布料和针脚，水手说潮位和缆绳，修女说灯油和祷告。

## 八、提交前自检

- 这段能不能删掉一半字还成立？能，就删。
- 选项是不是在写“结果”而不是“动作”？
- 失败有没有具体代价？还是只写“失败了”？
- 这一段第二次来会不会一模一样？
- 有没有出现 Lv、等级、经验、进度、奖励、任务完成？
- 图标是不是超过 4 个？有没有给闲聊加图标？
- 移动选项是不是在动作选项上面？
