# DoL-MP 设计标准（V33）

这份文件是给 Argon 和后续维护者的硬性规范。所有新内容、改稿、扩写都按这里执行。

## 1. 选项必须有来源和代价

- 来源只能是：属性达标、已获得的线索、已认识的 NPC、持有的物品/钱、正确的时间/地点。
- 代价必须可见：时间、钱、体力、压力、警戒、物品，至少一项。
- 不允许「凭空知道」：编号、暗格、密码、某人名字、某地入口，必须先通过观察/对话/线索获得。
- 不允许免费奖励；不允许失败分支发钱/发物品/写线索/加好感。

## 2. 门槛的呈现

- **属性不足**：选项正常显示，点进去才提示「需要 诡术等级：A」；不允许提前灰字「属性不足」。
- **时间不对**：同样点进去提示「需要 夜晚 或 黄昏 / 8:00–21:00」。
- **非属性状态**（钱不够、尚未结识、店铺打烊、伤势不重）可以灰字，因为主角本来就知道。
- 失败页统一走 `MP Insufficient` / `MP NotNow`，返回原页面。

## 3. 奖励与键

- 首通奖励的 `claimUniqueReward` 必须放在成功判定之后，失败不消耗。
- 可重复内容用每日键（`dailyKey + Time.days`），一次性内容用唯一静态键。
- 同一奖励只用一个键；键名带内容前缀，避免跨奖励共用。
- 失败至少消耗时间，并有 pain/stress/tiredness/警戒等代价。

## 4. NPC 与作息

- 作息用半开区间 `[开始, 结束)`；Hub、日志、街头偶遇、委托入口必须一致。
- 街头偶遇只在对应 NPC 的作息和地点出现。
- 时钟跨小时要刷新注入区；停在 Hub 上跨边界要重渲染在场/不在场分支。
- NPC 未结识时不得在选项标签里硬写名字。

## 5. 阶段与任务

- 阶段门槛阶梯：前段 260，中段 320–610，终章 800+；每条线至少两条属性路线。
- 线索加成只是捷径（+60/+600），不能替代属性。
- 不允许阶段跳档、跳章、越级完成；阶段增量要绑定对应阶段的行为。
- 每日键在判定成功后写，不在点击入口时写。
- 每条任务线必须有返回 Hub 的出口；不能出现无出口页面。

## 6. 随机事件

- 走原版 `eventpool`，进入地点时随机触发、占满屏幕，不做页面底部的内联提示行。
- 每件每天最多一次；触发时记录每日键和返回来路。
- 事件选项同样遵守来源/代价/失败不发奖。

## 7. UI 与文案

- 选项标签 4–8 个汉字（不含时间后缀），同页 ≤5 个正文选项。
- 单段最多 4 个图标，同段不重复；一个选项只能有一个图标。
- 复制粘贴的重试标签必须按场景改写，不能出现「刻痕」「暗槽机关」这种无关词。
- 出口文案与目标地点一致：返回矿道就不能去森林。
- 线索/物品反馈只在首次获得时显示。

## 8. 场景一致性

- 时间、地点、天气、在场 NPC 要与正文一致；白天不能写晚宴进行中。
- 选项不能引用该场景没出现的物件；需要时先在正文补一句可见线索。
- 失败/重试文案必须与动作对应。

## 9. 技术验收

- 72 个 twee、段落名唯一、断链 0、`if` 栈 0、BOM 0。
- `boot.json` 的 twee/img 列表与实际文件一致。
- 新增文件必须注册；新增图片必须进 `imgFileList`。
- 改动后跑 `_dev11_work/ifcheck_int.py` 和链接检查。
