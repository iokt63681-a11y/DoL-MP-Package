# 原版咖啡馆基准拆解（V34 修订）

基准不是独立「面包房」，而是原版 **Ocean Breeze 咖啡馆**里做小面包/咖啡的那条班次线。相关 passage 都在 `vanilla/vanilla-passages.twee`：

- `Cafe Coffee`
- `Cafe Coffee Creation`
- `Cafe Coffee Creation Results`
- `Cafe Coffee Flash`
- `Cafe Coffee Finish`
- `Cafe Pancakes`
- `Cafe Cream Bun`
- `Cafe Coffee Lewd`

## 它为什么值得对标

1. **一条班次有完整的“接单 → 制作 → 交付 → 结算”链**，不是一个 `pass` 加一句结果。
2. **制作有阶段**：咖啡按 small / medium / large / huge 分 4 档，不同档位对应不同产出、不同顾客反应、不同报酬。
3. **产品不止一种**：咖啡、面团/烤炉、煎饼、奶油小面包；每种都有自己的动作和结果。
4. **制作结果带随机分支**：`$phase` + `rng` 决定顾客满意/不满、给多少钱。
5. **老板和常客是具体的人**：Sam 会来收咖啡、道谢、给钱；贵族常客有独立反应。
6. **失败/暴露/情色分支是嵌在班次里的**，不是单独的弹窗。
7. **天气/时段会影响叙述**：雨、雪、白天/夜晚都有不同句子。
8. **薪酬和产出绑定**：做得多/做得好，钱和技能成长都不同。

## 迁移到本项目 12 条零工

下面这张表是**深度参照**，不是逐格填空的模板。每条零工要按自己工种的真实工序重新设计：咖啡馆是做咖啡/小面包，鱼档是分拣/下网，酒馆后厨是炸鱼排，马厩是刷马/装车。只学「接单 → 分档制作 → 交付 → 随机结果 → 常客/天气变化」的深度，不要机械复制同一套选项。

| 原版 Cafe 的做法 | 本项目对应 |
|---|---|
| 接单 | 班次开始时店东/常客提出具体需求 |
| 制作阶段（4 档） | 每个动作 2–4 个难度/产出档位，按技能或资历分档 |
| 交付 | 把成品交给店东/顾客，按结果结算 |
| 随机结果 | `random` + 技能决定满意/一般/失败 |
| 多产品 | 每条零工 2–3 种可做的活（如咖啡馆：冲咖啡/烤小面包/招待） |
| 具体老板/常客 | 每条零工 3 名具名常客，各有台词和偏好 |
| 天气/时段变化 | 晴/雨/雪、早/午/晚各至少 1 句 |
| 失败/暴露分支 | 嵌入班次，不单独弹窗；失败只扣状态 |
| 薪资绑定产出 | 工资公式按档位、技能、资历计算 |
| 技能成长 | 成功后给对应技能 +1 |

## Argon 的用法

先按这份基准复核 `MP Job Cafe` 与 `MP Job Bakery`，把它们做成两条样板；再把同样的“接单 → 分档制作 → 交付 → 随机结果 → 常客/天气变化”结构复制到其余 10 条零工。每条零工的 5 个专属插曲，本质上就是这套结构里的“顾客/工况小事件”，不是另写一段无关小故事。
